# API 投稿 2.0 桌面端设计

## 目标与边界

本程序是独立的 Windows 桌面投稿程序，固定目录为 `E:\自动化\api投稿2.0`。

- 不上传视频，不扫描上传目录，不处理出书表格。
- 固定读取飞书投稿表格的 `Sheet1`。
- 一行表格记录代表一本书对应的一条已上传视频，成功创建一个投稿单元后即完成该行。
- `E:\自动化\api`、`E:\自动化\api上传投稿` 及其他旧程序不读取、不修改、不覆盖。
- 授权、方案、日志、失败记录、运行数据库全部保存在本目录。

## 使用流程

1. 在桌面端粘贴巨量完整回调链接，导入并校验授权。
2. 点击“检测账户项目”，读取接口可访问的巨量账户及其项目。
3. 新建或切换投稿方案。
4. 在方案中勾选项目、上下拖动排序，并设置每个项目的当日投稿上限。
5. 点击启动。程序从 `Sheet1` 领取未投稿任务，按方案顺序投放。

## 桌面端页面

### 授权与连接

- 粘贴完整回调链接并导入授权。
- 显示 access token、refresh token 的有效状态和剩余有效期。
- 显示投稿表格连接状态以及固定子表名称 `Sheet1`。

### 账户与项目

- 显示接口检测到的巨量账户：账户名称、advertiser ID。
- 展开显示每个账户下的项目：项目名称、项目 ID。
- 支持手动刷新检测结果。
- 方案中的项目引用 advertiser ID 和 project ID，而不是只依赖名称；名称变化后仍能识别。

### 投稿方案

- 支持新建、复制、重命名、删除、保存、切换多套方案。
- 每套方案保存一个有序项目列表。
- 项目可勾选进入方案，支持上下拖动排序。
- 每个项目独立设置当日投稿上限。
- 项目失效、删除或无权限时显示异常，不自动改写方案。

### 运行状态

- 显示当前方案、当前项目、当前项目已投稿数/上限、下一个项目。
- 显示当日各项目计数、可领取任务数、待重试数、彻底失败数。
- 提供启动、停止、刷新状态按钮。
- 显示最近事件与可读的错误摘要。

## 投稿任务规则

1. 只读取 `Sheet1` 中未投稿的表格行。
2. 每行是一条视频任务。素材库按书名检索。
3. 只接受素材名称与书名完全一致的结果；若有多个完全相同名称的素材，取创建时间最新的一条。
4. 在当前项目所属巨量账户的素材库中检索并创建投稿单元。
5. 投稿成功后，将该表格行标记为已投稿；同一行不会再分配给后续项目。
6. 当前项目到达其当日上限后，切换到方案列表中的下一项目。
7. 全部已选项目到达上限后，不再领取新任务，状态显示为“全部满额等待次日”。
8. 按运行电脑本地时间每天 00:00 清零项目当日计数，自动从方案第一项目恢复执行。

## 失败与稳定性

- 可识别的临时接口错误先立即重试一次。
- 仍失败时，记录为待重试任务，一小时后再次尝试。
- 单条任务累计失败三次后标记为彻底失败。
- 失败任务不阻塞后续任务领取和投稿。
- 程序重启后通过本地 SQLite 数据库恢复方案计数、任务领取状态和失败次数。
- 令牌刷新、网络异常、项目不存在、素材不唯一等错误分别记录，并在桌面端显示。

## 验收标准

- 旧程序目录的文件校验值在开发期间保持不变。
- 可导入授权并检测到账户和项目。
- 可保存至少两套不同的项目顺序及上限方案。
- 项目可拖动排序；达到上限后按顺序切换。
- 一条表格行只产生一个投稿单元，并在成功后标记完成。
- 全项目满额后停止领取，到次日 00:00 自动清零并从首项目恢复。
- 一个任务失败不会停止后续任务；重试和三次失败规则可恢复、可查看。
