# 上传 + 投稿中心 1.0.17

Windows 本地桌面工具：从飞书读取任务，浏览器上传视频素材，通过巨量千川 API 投稿。
本仓库包含整合界面、API 投稿、视频上传模块、离线测试和打包脚本。

**另一台电脑的 Codex 接手先读 [HANDOFF.md](https://github.com/nmrsz645-bit/shangchuanXtougao/blob/main/HANDOFF.md#new-codex)**：源码入口、程序执行链、依赖、构建、已验证成果和缺项都在其中。完整/应用层更新包及发布步骤见 [RELEASE-GUIDE](https://github.com/nmrsz645-bit/shangchuanXtougao/blob/main/docs/RELEASE-GUIDE.md)，OSS 控制台的文件与目录对应见 [上传步骤](https://github.com/nmrsz645-bit/shangchuanXtougao/blob/main/docs/RELEASE-GUIDE.md#oss-upload)。源码推送不等于客户端或网站已更新。

## 安装与启动

1. 从本仓库 [GitHub Releases](https://github.com/nmrsz645-bit/shangchuanXtougao/releases/tag/v1.0.17) 下载 `shang-chuan-tou-gao-zhong-xin-1.0.17-github-windows-x64.zip`；普通用户不要下载 Source code ZIP 代替程序包。
2. 根据 Release 的 `SHA256SUMS.txt`，用 PowerShell `Get-FileHash -Algorithm SHA256 <ZIP路径>` 核对文件。
3. 完整解压到可写的新目录，例如 `D:\Apps\UploadPostingCenter`；Windows 10/11 x64，无需安装 Python。
4. 安装正式版 Google Chrome；联网访问飞书、巨量和更新服务。
5. **双击完整包根目录 `Start.cmd`**。它先同步运行 `updater\UpdateAgent.exe`，再调用 `app\Start-App.cmd` 启动程序。直接打开 EXE 会绕过更新检查。

完整包包含 `Start.cmd`、`app/`、`updater/`、`README.md`、`HANDOFF.md`、安全空配置示例与 `BUILD-INFO.json`。
程序未经本项目的代码签名证书签名；请校验来源和散列，不要关闭安全软件。

## 首次配置

第一次先保持自动运行相关选项关闭，完成配置、预览和小批验证后再启用。

| 项目 | 从哪里取得、填写在哪里 |
| --- | --- |
| 飞书 App ID / Secret | 自己组织的飞书开放平台企业自建应用“凭证与基础信息”；在整合界面“飞书设置”填写并保存。授予实际所用云文档读写权限，并将应用加入目标表格可访问范围。 |
| 上传/投稿表格、复制表链接 | 在自己有权限的飞书表格复制链接，填对应字段；Wiki 与 Sheets 访问还受应用权限影响。不要把仅浏览器本人可见视为应用已有权限。 |
| 千川 App ID / Secret | 自己的巨量开放平台应用凭证，填“API 投稿→授权”。真实 Secret 不属于源码。 |
| 授权回调 | 用该应用的正式授权流程取得完整回调链接，填“完整回调链接”后“导入授权”；不能把别人的 token 复制过来。回调链接本身可能含短期凭证，不要公开。 |
| 指定账户 ID | 目标广告账号后台查看，按授权范围填写；留空沿用已授权账户选择逻辑。 |
| 当前小程序 App ID | 自己的小程序后台取得；填“当前小程序 App ID”。留空保留既有程序链接判断规则。 |
| 巨量素材库地址 | 浏览器切到自己正确广告账号的素材中心复制地址，填“视频上传”对应字段。新安装不再预填具体账号。 |
| 源/目标文件夹 | 在“视频上传”选择本机目录。预览会显示移动/匹配结果，执行可能移动文件并写表。 |
| Chrome 登录 | 点击“打开巨量登录页面”并由本人登录；程序使用独立持久资料，不读取系统浏览器 Cookie。 |

安全空示例见 `examples/`；它们只说明字段结构，不会自动导入，也不能替代平台授权。
运行时请通过界面保存设置；上传模块的 Secret 使用 Windows keyring，整合/API 设置还可能在本机 JSON 中保存凭证，应限制文件访问。

## 主要操作

### 视频上传

1. 保存飞书、目录和素材库地址，点击“测试连接”。
2. 点击“扫描预览”，核对文件名、书名、目标路径及“可执行/未匹配/目标同名跳过”。
3. 检查复制表包含唯一的 `书名`、`标签`、`活动页`、`程序链接` 表头。文件名去扩展名后与书名精确匹配，同书名后行覆盖前行。
4. “开始执行”只执行预览中的文件移动与飞书追加，不会直接启动浏览器上传。“启动自动上传”才会启动上传循环，并再次扫描/提取、上传目标文件夹的待传素材；单批上传也需使用它。
   确认目标账号和目标文件夹内全部待传文件后，再点击“启动自动上传”；仅做一批时等该批完成核验后点击“停止自动上传”，不要在仍处理文件时强制退出。
   **当前程序会删除已核验上传成功的目标视频，前序源文件已移动，程序不会自动保留原片副本。需要留存视频时，运行前先按用户授权保留独立媒体备份。**
5. 上传到 100% 后程序仍须点击上传面板的“确定”并等待平台入库，不应只凭进度条认定成功。
6. 可选“请确认【仅IAA】素材”弹窗出现时，程序在检测到零勾选状态后只点该弹窗“确认”，等待关闭；不点击复选框。已选中、半选或结构异常时停止确认并报错。
7. 成功通过平台回执和目标账号素材核验后才记录成功。按需开启“上传成功后写入飞书 E 列”，不要把勾选写表等同于仅预览。
8. “重试写表失败项”用于写表恢复，先看日志和原记录，避免把已经入库的素材重复上传。

### API 投稿

1. “授权”页保存连接与导入授权。
2. “账户项目”页检测可用项目。
3. “投稿方案”中新建方案，加入项目，核对顺序、每日数量及速度；自动代理选项会影响实际任务分配。
4. “运行状态”点击“启动投稿”；停止时使用“停止投稿”，保留数据库与日志。
5. 任务表要求 `书名、标签、启动页、程序链接、领取状态、领取电脑、领取时间、领取批次号、领取过期时间、投稿状态` 等字段。领取与回写会真实修改表格。

整合界面还提供开机启动、启动后自动执行和每日重启检查。首次配置不要开启自动任务；调试时也不要借开机启动运行真实队列。

## 常见问题

| 现象 | 检查与处理 |
| --- | --- |
| 没有更新/仍显示旧版 | 结束任务后正常退出旧窗口，从安装根目录 `Start.cmd` 启动；检查网络、`updater` 是否完整、`app/version.json` 与窗口版本。不要直接双击 EXE。 |
| “程序已经在运行” | 检查旧窗口或已有任务；不要强杀工作进程或删除运行锁。 |
| 书在表中却“未匹配” | 核对复制表地址、文件名和表头。表头会去两端空格，重复“书名”会选第一列，可能误选日期列；先核查，不直接改业务表。 |
| 飞书 403/无权限/缺表头 | 核对应用权限、表格访问范围、链接及各模块不同表头要求；浏览器能打开不代表应用能访问。 |
| 100% 后仍等待 | 平台还需确定、可选 IAA 确认和入库核验。保留日志并观察界面，不手动连点或盲目重传。 |
| IAA 确认失败 | 检查是否已经有勾选、是否换了弹窗结构；交给本人判断，程序不会自动取消勾选。 |
| 待上传文件不存在 | 对照实际文件、移动记录和本轮任务状态；这与飞书匹配是不同阶段，不要直接清空队列。 |
| 授权过期/账户不在列表 | 在正确应用下重新走本人授权，核对账户权限和指定账户配置，不分享回调或 token。 |
| 无法打开 Chrome | 安装正式版 Google Chrome；本项目不要求额外安装 Playwright 自带浏览器。 |
| 源码启动缺模块 | 用下方指定虚拟环境安装依赖，再启动；不要混用系统 Python 3.10。 |

## 数据保护

源码运行时：根 `共享飞书设置.json`；`API投稿2.0/config`、`data/state.db`、`logs`；`自动上传/个人数据`。
打包运行时：上述共享/API 路径在 `app/` 下，上传模块数据默认在 `app/个人数据`。`AUTO_UPLOAD_DATA_DIR` 可为上传模块指定外部数据位置。
这些目录包含授权、Chrome 资料、任务和日志：不提交、不打包、不上传，不因失败删除。仓库与示例均不含真实账号凭证。

## 开发与离线测试

Windows + Git + Python 3.13 x64（本次为 3.13.15），在可写目录：

```powershell
git clone https://github.com/nmrsz645-bit/shangchuanXtougao.git
Set-Location shangchuanXtougao
py -3.13 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements-build-windows.txt
.\.venv\Scripts\python.exe -B -m pytest -q -p no:cacheprovider test_center_startup.py test_daily_restart.py test_shared_feishu.py test_handoff_safety.py test_release_safety.py test_github_package.py API投稿2.0/tests 自动上传/tests
```

开发启动：`启动投稿中心.vbs` / `启动投稿中心.bat` 或 `.\.venv\Scripts\python.exe 投稿中心.py`。它们使用源码入口，不是发行包的更新入口。
`requirements-build-windows.txt` 会引用 `requirements-dev.txt` 安装模块和离线测试依赖，并固定本次直接构建依赖版本。
测试使用模拟接口；开发启动会加载本机设置，可能启用已保存自动任务，必须先取得真实运行授权。
完整构建、GitHub 发布、模块修改入口和已知限制见 [HANDOFF.md](HANDOFF.md)。
